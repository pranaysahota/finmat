Stock Analysis Evals

A practical approach for evaluating non-deterministic stock-analysis runs in finmat without pretending the model output should be byte-for-byte stable.

Target workflows: daily Growth + watchlist briefing, weekly all-stock briefing, Gemini stock analysis, Gemini sell recommendations, and Anthropic sentiment scoring.

What We Should Evaluate

Correct Scope

Daily runs must cover Growth holdings plus watchlist tickers only. Weekly runs must cover all held stock positions.

deterministic CI-safe

Financial Safety

Sell guidance must not invent holdings, ignore losses/gains, or recommend a sale without a reason tied to supplied data.

rubric human-reviewable

Grounding

Analysis should distinguish supplied portfolio data from searched/news-backed claims and avoid unsupported certainty.

LLM judge sampled

Output Usefulness

The result should be concise, ticker-specific, and actionable enough to review quickly from an email digest.

rubric thresholded

Test Shape

Do not use golden full-text snapshots. For model outputs, exact text snapshots create noisy failures and encourage worse prompts. Instead, save the inputs, parse the output, and score properties that should remain true across valid generations.

  1. Create fixtures for portfolio state, performance, triggered rules, sentiment, macro themes, and watchlist tickers.
  2. Run the prompt-building layer deterministically and assert required tickers, sections, values, and exclusions.
  3. Run model calls behind a small eval harness that records inputs, outputs, model name, prompt version, and timestamp.
  4. Score outputs with a mix of hard checks, lightweight parsers, and an LLM judge rubric.
  5. Store eval reports as HTML or JSON artifacts so regressions can be reviewed later.

Scoring Layers

Scope Required tickers present, forbidden tickers absent, watchlist labelled as non-held, crypto excluded from all-stock equity briefing.
Structure Expected sections exist, each scoped ticker receives a section, sell recommendations use only HOLD, WATCH, or SELL for held positions.
Numerics Portfolio value, P&L, cost basis, and CGT calculations stay within tolerance of supplied inputs.
Grounding Claims cite supplied sentiment or search-backed context, and the output avoids invented positions, prices, or tax rules.
Tone Concise, appropriately uncertain, no hype, no absolute buy/sell language unsupported by evidence.

Pass Criteria

Each eval run can report one of three states:

  • Pass: hard checks pass and rubric score is at or above threshold.
  • Review: hard checks pass but rubric score is borderline, or output changed materially from the last accepted run.
  • Fail: required ticker scope, structure, numeric, or safety checks fail.

Implementation Plan

  1. Add prompt-builder tests first, because they are deterministic and cheap.
  2. Add evals/fixtures/ with sanitized portfolio states and no private holdings beyond fake test data.
  3. Add scripts/run_stock_analysis_evals.py with --offline for mocked model outputs and --live for sampled provider calls.
  4. Write eval output to evals/reports/, gitignored by default unless we decide to commit curated examples.
  5. Run offline evals in CI on every PR. Run live evals manually or on a scheduled job with test credentials.

Recommended First Rubric

Score 1-5 each: scope accuracy, factual consistency with inputs, tax/financial safety, grounding quality, and concision.

Fail automatically if: a non-scoped ticker is analyzed, a watchlist ticker receives a sell verdict, a numeric value contradicts supplied inputs by more than an agreed tolerance, or the output invents a holding.

Promote to production prompt change only if: average score is 4.0 or above and all hard checks pass across the baseline fixtures.
